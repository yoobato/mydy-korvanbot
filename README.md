# KoreaVancouverBot

주밴쿠버 대한민국 총영사관 홈페이지의 새 게시글을 텔레그램으로 알려주는 비공식 알림 서비스입니다.

[채널 구독](https://t.me/korea_vancouver) · [봇](https://t.me/KoreaVancouverBot)

## 모니터링 게시판

- [공지사항](https://www.mofa.go.kr/ca-vancouver-ko/brd/m_4585/list.do)
- [순회영사](https://www.mofa.go.kr/ca-vancouver-ko/brd/m_20174/list.do)
- [해외여행안전정보](https://www.mofa.go.kr/ca-vancouver-ko/brd/m_27536/list.do)
- [동포/지역한인회 소식](https://www.mofa.go.kr/ca-vancouver-ko/brd/m_24795/list.do)

자료 출처는 [총영사관 공식 홈페이지](https://www.mofa.go.kr/ca-vancouver-ko/index.do)이며,
공지사항은 [공식 RSS](https://www.mofa.go.kr/ca-vancouver-ko/brd/rss.do?brdId=4004)도 확인합니다.

## 동작 원리

1. **1시간 주기**로 각 게시판의 최근 3페이지를 확인합니다.
2. 첫 실행에서는 기존 글을 기록만 하고, 이후 새로 발견한 글부터 알림을 보냅니다.
3. **🔔 게시판 → 📅 날짜 → 📝 제목 → 본문 요약 → 원문 링크** 순서로 채널에 게시합니다.
4. 전송 기록으로 중복 알림을 줄이고, 실패한 전송은 다음 확인에서 재시도합니다.

항목 사이에는 한 줄씩 띄우고, 날짜는 2026-09-30 (수) 형식의 일반 텍스트로 표시합니다.
본문 요약은 도입부와 일시·장소·신청 안내를 최대 320자로 발췌하며, 이미지뿐인 글은 원문 확인 안내를 표시합니다.

제목 수정은 새 알림을 만들지 않습니다. 같은 공지가 여러 게시판에 올라오면 각각 알림을 보냅니다.
오랜 중단으로 조회 범위를 벗어난 글은 놓칠 수 있고, 전송 응답이 유실되면 중복 알림이 발생할 수 있습니다.

게시판·확인 주기는 `boards.json`, 환경변수 예시는 `.env.example`을 참고하세요.
실제 `.env`와 게시글 기록은 저장소에 포함하지 않습니다.

## 수집·파싱 방식

별도 JSON API나 브라우저 자동화 없이, 공식 홈페이지의 HTML과 RSS XML을 HTTP 요청으로 가져옵니다. `boards.json`은 수집 대상과 주기를 정하는 설정 파일이며, 홈페이지에서 제공하는 데이터 API가 아닙니다.

| 게시판 | 새 글 목록 수집 | 본문 수집 |
| --- | --- | --- |
| 공지사항 (`m_4585`) | 공식 RSS (`brdId=4004`) + HTML 목록 최근 3페이지 | 원문 HTML |
| 순회영사 (`m_20174`) | HTML 목록 최근 3페이지 | 원문 HTML |
| 해외여행안전정보 (`m_27536`) | HTML 목록 최근 3페이지 | 원문 HTML |
| 동포/지역한인회 소식 (`m_24795`) | HTML 목록 최근 3페이지 | 원문 HTML |

### 목록과 새 글 판별

- HTML 목록은 각 게시판의 `list.do?page=1`부터 3페이지까지 읽습니다. 표의 행(`tr`)에서 제목 링크의 `onclick`에 있는 `f_view('글번호', ...)`, 링크 텍스트, `YYYY-MM-DD` 날짜를 추출하고 `view.do?seq=글번호` 원문 주소를 구성합니다. 공관 활동 게시판은 수집하지 않습니다.
- 공지사항 RSS는 `channel/item`의 `title`, `link`, `pubDate`를 읽습니다. 피드의 `http://www.mofa.go.kr:443` 링크는 정상 HTTPS 주소로 바꿉니다. RSS에 없는 고정 공지나 이전 글도 확인하도록 HTML 목록을 항상 함께 읽으며, 같은 URL은 합치고 목록의 제목·날짜를 우선합니다. RSS 오류가 나도 HTML 수집을 계속합니다.
- 글번호 순으로 정렬한 뒤 SQLite에 원문 URL을 저장해 새 글을 구분합니다. 첫 수집의 기존 글은 발송하지 않으며, 이후 처음 발견한 URL만 발송 대기 상태로 기록합니다. 이미 기록한 글의 제목·본문 수정은 재발송하지 않습니다.

### 본문과 요약

발송할 글은 `view.do?seq=글번호`를 다시 요청합니다. `.bo_head`에서 작성일을 읽어 목록 날짜보다 우선하고, `.bo_con` 영역에서 본문 텍스트와 이미지 유무를 추출합니다. 메뉴·페이지 바깥 영역과 본문의 `script`, `style` 내용은 포함하지 않으며, 문단·목록·표의 행·`br`을 줄바꿈으로 바꿉니다.

요약은 **AI 요약이 아닌 원문 발췌**입니다. 중복 제목과 사진 설명으로 시작하는 줄을 제외하고, 첫 문단과 `일시:`, `일자:`, `장소:`, `신청 기간:`, `접수 기간:`, `예약 기간:`, `온라인 예약:`, `마감:` 안내 중 최대 3개를 선택합니다. 해당 안내가 없으면 앞의 두 문단을 선택합니다. 문단 간격과 한국어 문장 줄바꿈을 정리하고 최대 320자로 줄여 표시합니다.

이미지 안의 글자(OCR)나 첨부 PDF·문서 내용은 읽지 않습니다. 본문에 텍스트 없이 이미지만 있으면 원문 이미지 확인 안내를, 텍스트와 이미지가 모두 없으면 원문 확인 안내를 보냅니다. 전체 내용과 첨부파일은 원문 링크에서 확인해야 합니다.

목록에서 인식 가능한 글이 없거나 원문의 본문 영역을 찾지 못하면 파싱 오류로 처리합니다. 목록 오류 시 해당 게시판의 수집 기록을 갱신하지 않고, 원문 오류 시 발송 대기 글을 보관해 다음 확인에서 재시도합니다.

## 소개 웹사이트

`site/`의 정적 소개 페이지를 GitHub Actions로 GitHub Pages에 배포합니다. `main`에서 소개 페이지나 배포 설정이 바뀌면 자동 배포합니다. 텔레그램 수집 워커는 기존 서버에서 별도로 실행됩니다.

- 기본 주소: https://yoobato.github.io/mydy-korvanbot/
- 연결 예정 도메인: `korvanbot.mydy.kr` — DNS에 `korvanbot` CNAME을 `yoobato.github.io`로 연결한 뒤 GitHub Pages의 Custom domain과 HTTPS를 설정합니다.

## 장애 알림

`TELEGRAM_ADMIN_CHAT_ID`를 설정하면 수집·파싱, RSS, 원문 조회, 채널 전송 오류를 운영자의 개인 텔레그램으로 알립니다.
운영자는 먼저 봇과의 개인 채팅에서 `/start`를 보내야 합니다.
같은 장애는 한 번만 알리고, 복구를 확인하면 한 번 더 알립니다. 장애 기록은 재시작 후에도 유지하며, 알림 전송 실패는 다음 확인에서 재시도합니다.
공개 채널에는 게시글 알림만 올라갑니다. 서버나 봇 자체가 중단되거나 텔레그램에 연결할 수 없는 동안에는 개인 알림도 보낼 수 없습니다.
