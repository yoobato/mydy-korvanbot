# KoreaVancouverBot

주밴쿠버 대한민국 총영사관 홈페이지의 새 게시글과 내용 수정을 텔레그램으로 알려주는 비공식 알림 서비스입니다.

[채널 구독](https://t.me/korea_vancouver) · [봇](https://t.me/KoreaVancouverBot)

## 모니터링 게시판

- [공지사항](https://www.mofa.go.kr/ca-vancouver-ko/brd/m_4585/list.do)
- [순회영사](https://www.mofa.go.kr/ca-vancouver-ko/brd/m_20174/list.do)
- [해외여행안전정보](https://www.mofa.go.kr/ca-vancouver-ko/brd/m_27536/list.do)
- [동포/지역한인회 소식](https://www.mofa.go.kr/ca-vancouver-ko/brd/m_24795/list.do)

자료 출처는 [총영사관 공식 홈페이지](https://www.mofa.go.kr/ca-vancouver-ko/index.do)이며,
공지사항은 [공식 RSS](https://www.mofa.go.kr/ca-vancouver-ko/brd/rss.do?brdId=4004)도 확인합니다.

## 동작 원리

1. **한 차례 확인이 끝난 뒤 60분 후** 각 게시판의 최근 3페이지를 다시 확인합니다. 수집·재시도에 걸린 시간만큼 시작 시각 간격은 길어집니다.
2. 첫 실행에서는 기존 글을 기록만 하고, 이후 새로 발견한 글부터 알림을 보냅니다.
3. **🔔 게시판 → 📅 날짜 → 📝 제목 → 본문 요약 → 원문 링크** 순서로 채널에 게시합니다.
4. 최근 목록에 있는 글은 매 확인 주기마다, 목록에서 벗어난 저장된 글은 마지막 확인으로부터 24시간이 지나면 원문을 다시 읽습니다. 제목·본문이 바뀌면 **📝 게시글 수정** 알림을 따로 보냅니다.
5. 전송 기록으로 중복 알림을 줄이고, 실패한 전송은 다음 확인에서 재시도합니다.

항목 사이에는 한 줄씩 띄우고, 날짜는 2026-09-30 (수) 형식의 일반 텍스트로 표시합니다.
본문 요약은 도입부와 일시·장소·신청 안내를 최대 320자로 발췌하며, 이미지뿐인 글은 원문 확인 안내를 표시합니다.

수정 감지를 처음 적용할 때는 현재 내용을 비교 기준으로 저장하고, 그 이후 확인한 변경부터 알립니다. 기존 텔레그램 메시지는 그대로 유지합니다. 같은 공지가 여러 게시판에 올라오면 각각 알림을 보냅니다.
오랜 중단으로 조회 범위를 벗어난 글은 놓칠 수 있고, 전송 응답이 유실되면 중복 알림이 발생할 수 있습니다.

게시판·확인 주기는 `boards.json`, 환경변수 예시는 `.env.example`을 참고하세요.
실제 `.env`와 게시글 기록은 저장소에 포함하지 않습니다.

## 수집·파싱 방식

별도 JSON API나 브라우저 자동화 없이, 공식 홈페이지의 HTML과 RSS XML을 HTTP 요청으로 가져옵니다. `boards.json`은 수집 대상과 주기를 정하는 설정 파일이며, 홈페이지에서 제공하는 데이터 API가 아닙니다.

모든 RSS·목록·본문 요청은 **`overseas.mofa.go.kr`을 먼저** 사용하고, 연결·HTTP 오류 또는 응답 파싱 실패 시 **`www.mofa.go.kr`로 전환**합니다. 현재 두 주소는 각각 `116.67.79.27`, `116.67.79.26`으로 조회되지만, IP를 코드에 고정하지 않고 도메인으로 연결합니다. 같은 IP를 가리키는 `vancouver.mofa.go.kr`은 별도 백업으로 시도하지 않습니다. 기본 주소는 매 요청에서 다시 우선하며, 인증서는 두 주소 모두 검증합니다.

중복 판별용 원문 URL은 기존 `www.mofa.go.kr` 형식을 유지합니다. 실제 수집 도메인이 바뀌어도 기존 글이 새 글로 취급되지 않으며, 기존 데이터베이스를 초기화하지 않습니다.

| 게시판 | 새 글 목록 수집 | 본문 수집 |
| --- | --- | --- |
| 공지사항 (`m_4585`) | 공식 RSS (`brdId=4004`) + HTML 목록 최근 3페이지 | 원문 HTML |
| 순회영사 (`m_20174`) | HTML 목록 최근 3페이지 | 원문 HTML |
| 해외여행안전정보 (`m_27536`) | HTML 목록 최근 3페이지 | 원문 HTML |
| 동포/지역한인회 소식 (`m_24795`) | HTML 목록 최근 3페이지 | 원문 HTML |

### 목록과 새 글 판별

- HTML 목록은 각 게시판의 `list.do?page=1`부터 3페이지까지 읽습니다. 표의 행(`tr`)에서 제목 링크의 `onclick`에 있는 `f_view('글번호', ...)`, 링크 텍스트, `YYYY-MM-DD` 날짜를 추출하고 `view.do?seq=글번호` 원문 주소를 구성합니다. 공관 활동 게시판은 수집하지 않습니다.
- 공지사항 RSS는 `channel/item`의 `title`, `link`, `pubDate`를 읽습니다. 피드의 `http://www.mofa.go.kr:443` 링크는 정상 HTTPS 주소로 바꿉니다. RSS에 없는 고정 공지나 이전 글도 확인하도록 HTML 목록을 항상 함께 읽으며, 같은 URL은 합치고 목록의 제목·날짜를 우선합니다. RSS 오류가 나도 HTML 수집을 계속합니다.
- 글번호 순으로 정렬한 뒤 SQLite에 원문 URL을 저장해 새 글을 구분합니다. 첫 수집의 기존 글은 발송하지 않으며, 이후 처음 발견한 URL만 발송 대기 상태로 기록합니다. 이미 기록한 글은 새 글 알림과 별개로 아래 수정 감지 절차를 적용합니다.

### 본문과 요약

발송할 글과 수정 여부를 확인할 글은 `view.do?seq=글번호`를 다시 요청합니다. `.bo_head h2`에서 공지 배지를 제외한 현재 제목을 읽습니다. `.bo_head`에서 작성일을 읽어 목록 날짜보다 우선하고, `.bo_con` 영역에서 본문 텍스트와 이미지 유무를 추출합니다. 메뉴·페이지 바깥 영역과 본문의 `script`, `style` 내용은 포함하지 않으며, 문단·목록·표의 행·`br`을 줄바꿈으로 바꿉니다.

요약은 **AI 요약이 아닌 원문 발췌**입니다. 중복 제목과 사진 설명으로 시작하는 줄을 제외하고, 첫 문단과 `일시:`, `일자:`, `장소:`, `신청 기간:`, `접수 기간:`, `예약 기간:`, `온라인 예약:`, `마감:` 안내 중 최대 3개를 선택합니다. 해당 안내가 없으면 앞의 두 문단을 선택합니다. 문단 간격과 한국어 문장 줄바꿈을 정리하고 최대 320자로 줄여 표시합니다.

이미지 안의 글자(OCR)나 첨부 PDF·문서 내용은 읽지 않습니다. 본문에 텍스트 없이 이미지만 있으면 원문 이미지 확인 안내를, 텍스트와 이미지가 모두 없으면 원문 확인 안내를 보냅니다. 전체 내용과 첨부파일은 원문 링크에서 확인해야 합니다.

목록에서 인식 가능한 글이 없거나 원문의 본문 영역을 찾지 못하면 파싱 오류로 처리합니다. 목록 오류 시 해당 게시판의 수집 기록을 갱신하지 않고, 원문 오류 시 발송 대기 글을 보관해 다음 확인에서 재시도합니다.

### 수정 감지

- 최근 글은 각 게시판의 최근 3페이지와 RSS에서 확인한 URL을 뜻합니다. 매 모니터링 주기에 원문을 다시 읽으며, 그 밖의 **이미 저장된 글**은 마지막 확인 후 24시간이 지나면 다시 읽습니다. 과거 게시판 전체를 새로 탐색하지 않으며, 모니터링에서 제외한 게시판은 재조회하지 않습니다.
- 제목과 **본문 전체**의 공백·줄바꿈·유니코드 표현을 정리한 뒤, 본문 이미지·링크 주소와 함께 SHA-256 지문을 저장합니다. 원문 발췌 320자 밖의 변경도 감지하고, 서식·공백만 달라지거나 기본·백업 도메인이 바뀌면 알리지 않습니다. 작성일·수정일 표시만 바뀌는 경우도 별도 알림을 만들지 않습니다.
- 첫 조회는 알림 없이 비교 기준을 저장합니다. 이후 지문이 달라지면 최신 제목·작성일·본문 발췌·원문 링크를 담은 **📝 게시글 수정** 알림을 새 메시지로 보냅니다. 기존 글과 수정된 부분을 대조한 목록은 제공하지 않습니다.
- 조회나 수정 알림 전송에 실패하면 이전 지문과 확인 시각을 유지해 다음 주기에 다시 시도합니다. 성공한 수정 알림은 같은 내용으로 반복하지 않습니다. 다만 전송 응답이 유실되면 중복될 수 있으며, 확인 사이에 여러 번 수정된 내용은 마지막 상태만 비교할 수 있습니다.
- 이미지·본문 링크의 주소가 바뀌면 감지하지만, **같은 주소의 파일 내용 교체**, 이미지 속 글자, 별도 첨부 영역의 파일 변경은 확인하지 않습니다. 서버에 저장된 이전 발송 기록은 유지하며 비교 지문용 테이블만 추가합니다.

## 소개 웹사이트

소개 페이지는 총영사관 관할지역(BC·알버타·서스캐처원·유콘·노스웨스트 준주)을 위한 알림 서비스를 안내합니다. 실제 [2026년 11월 캘거리 순회영사 공지](https://www.mofa.go.kr/ca-vancouver-ko/brd/m_4585/view.do?seq=1347776&page=1)를 알림 예시로 사용하고, HTML·RSS 수집과 원문 발췌 방식을 설명합니다. 게시판과 예시 원문 링크는 새 탭으로 열립니다. 관할지역 출처는 [주캐나다 대한민국 대사관의 총영사관 안내](https://www.mofa.go.kr/ca-ko/wpge/m_5340/contents.do)입니다.

`site/`의 정적 소개 페이지를 GitHub Actions로 GitHub Pages에 배포합니다. `main`에서 소개 페이지나 배포 설정이 바뀌면 자동 배포합니다. 텔레그램 수집 워커는 기존 서버에서 별도로 실행됩니다.

- 소개 페이지: https://korvanbot.mydy.kr/
- 검색용 제목·설명, 대표 URL, WebSite/WebPage 구조화 데이터와 `robots.txt`·`sitemap.xml`을 제공합니다. 링크 공유에는 `og.png`(1200×630)와 Open Graph·X 카드 메타데이터를 사용합니다. 페이지 내용 수정 시 사이트맵의 `lastmod`도 갱신합니다.
- `korvanbot` CNAME은 `yoobato.github.io`로 연결하며, GitHub Pages의 Custom domain으로 등록합니다. 도메인 설정은 GitHub Pages에서 관리하며, Actions 배포에는 `CNAME` 파일이 필요하지 않습니다.

## 장애 알림

`TELEGRAM_ADMIN_CHAT_ID`를 설정하면 수집·파싱, RSS, 원문 조회, 채널 전송 오류를 운영자의 개인 텔레그램으로 알립니다.
운영자는 먼저 봇과의 개인 채팅에서 `/start`를 보내야 합니다.
같은 장애는 한 번만 알리고, 복구를 확인하면 한 번 더 알립니다. 장애 기록은 재시작 후에도 유지하며, 알림 전송 실패는 다음 확인에서 재시도합니다.
각 도메인의 요청은 제한시간 25초를 사용하며, 일시적인 연결 오류·HTTP 429/일부 5xx 오류는 1초·2초 간격으로 최대 2회 더 시도합니다. 인증서 검증 실패·HTTP 404·파싱 실패는 같은 도메인에서 반복하지 않고 백업 주소로 전환합니다. 두 주소가 모두 실패하면 기존 수집·발송 기록을 보존하고 다음 확인 주기에 재시도합니다.

개인 장애 알림에는 기본·백업의 실패 URL과 각각의 원인을 표시합니다. 연결 시간 초과·DNS·TLS·인증서·HTTP 상태를 구분하며, 파싱 오류는 단순히 `ValueError`로 알리지 않습니다. 예를 들어 목록의 몇 페이지에서 글번호·제목·작성일을 인식하지 못했는지, 원문의 `.bo_con` 본문 영역이 없는지, RSS XML의 몇 번째 줄을 해석할 수 없는지 안내합니다. 응답 본문과 토큰은 알림에 포함하지 않습니다. 백업 주소로 수집에 성공하면 장애 알림 없이 수집을 계속하며 전환 내역은 서버 로그에 남깁니다.
공개 채널에는 게시글 알림만 올라갑니다. 서버나 봇 자체가 중단되거나 텔레그램에 연결할 수 없는 동안에는 개인 알림도 보낼 수 없습니다.

## 페이지 구성

초록색·크림색 디자인으로 관할지역 지도와 수집 과정 그림을 제공합니다. 기술 설명은 펼쳐볼 수 있으며, 화면 진입 효과와 5초 이내에 끝나는 전달 애니메이션은 시스템의 동작 줄이기 설정을 존중합니다.

국문(`/`)·영문(`/en/`) 페이지를 제공합니다. 루트 주소의 첫 접속은 브라우저 우선 언어가 한국어이면 국문, 나머지는 영문으로 연결합니다. 직접 `/en/`으로 접속하면 영문을 유지합니다. KO/EN 선택은 브라우저에 저장되며 이후 자동 선택보다 우선합니다. 영문 페이지에도 실제 알림은 한국어로만 지원된다고 안내합니다.

지도는 [Natural Earth의 캐나다 주·준주 경계 데이터](https://github.com/nvkelso/natural-earth-vector/blob/master/geojson/ne_50m_admin_1_states_provinces.geojson)를 단순화한 SVG입니다. 데이터는 [퍼블릭 도메인](https://www.naturalearthdata.com/about/terms-of-use/)이며, 관할지역 확인 출처는 위 대사관 안내를 참고하세요.

국문·영문 지도는 캐나다의 10개 주와 3개 준주를 약어로 표시합니다. 동부의 NB·NS·PE에만 짧은 연결선을 사용하고 여백을 줄여 모바일에서 지도가 넓게 보이도록 했습니다. 경계 구분은 [캐나다 정부의 주·준주 안내](https://www.canada.ca/en/immigration-refugees-citizenship/services/settle-canada/provinces-territories.html), 강조 지역은 [주캐나다 대한민국 대사관 관할지역 안내](https://www.mofa.go.kr/ca-ko/wpge/m_5340/contents.do)와 대조했습니다. 수집 방식 펼치기에는 단계별 안내, 실제 읽는 주소와 알림 동작을 정리하고, 푸터는 서비스 안내 박스와 외부 링크로 구분합니다. 지도는 관할지역 설명을 위한 단순화된 경계도입니다.

펼치기 안내는 닫힌 상태와 열린 상태가 같은 패널 디자인을 사용하며, 열기·닫기 높이를 약 0.3초에 걸쳐 전환합니다. 동작 줄이기를 사용하면 즉시 전환하고, JavaScript 없이도 기본 펼치기가 동작합니다. 지도 약어는 작은 화면에서는 기존 크기, 큰 지도에서는 약간 작게 표시합니다.
